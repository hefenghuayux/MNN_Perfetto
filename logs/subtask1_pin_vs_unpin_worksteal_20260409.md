# 子任务1：当前 work_steal 版本下的“绑核 vs 不绑核”

## 实验口径

- 测试包：`/data/local/tmp/work_steal_decode_blocks_current`
- 调度策略：`prefill=work_steal`，`decode=dynamic`
- 输入：`prompt=512`，`decode=128`
- 统计口径：`1` 次 warmup + `5` 次测量，报告 `mean ± std`
- 指标：
  - `pp512`：Prefill 平均时延（ms）
  - `tg128`：Decode 平均时延（ms）
  - `E2E`：`pp512 + tg128`
  - `Prefill tok/s`
  - `Decode tok/s`

原始文件：

- `logs/subtask1_pin_vs_unpin_worksteal_raw_20260409.txt`
- `logs/subtask1_pin_vs_unpin_worksteal_summary_20260409.tsv`

## 同线程对比

### 4 线程

- `4 -> 4,5,6,7`
- `pp512`：`1178.86 -> 1115.48 ms`，下降约 `5.38%`
- `tg128`：`1475.07 -> 1348.36 ms`，下降约 `8.59%`
- `E2E`：`2653.93 -> 2463.84 ms`，下降约 `7.17%`

### 5 线程

- `5 -> 3,4,5,6,7`
- `pp512`：`963.03 -> 931.80 ms`，下降约 `3.24%`
- `tg128`：`1332.41 -> 1344.62 ms`，上升约 `0.92%`
- `E2E`：`2295.44 -> 2276.42 ms`，下降约 `0.83%`

### 6 线程

- `6 -> 2,3,4,5,6,7`
- `pp512`：`844.51 -> 847.60 ms`，上升约 `0.37%`
- `tg128`：`1356.19 -> 1345.31 ms`，下降约 `0.80%`
- `E2E`：`2200.70 -> 2192.91 ms`，下降约 `0.35%`

## 结论

1. 在当前 `work_steal` 版本下，绑核收益不是“所有线程数都同样明显”。
2. `4` 线程是最明显的受益点，绑到 `4,5,6,7` 后，Prefill、Decode、端到端都显著改善。
3. `5` 线程时，绑核主要改善 Prefill，但 Decode 略有回退，因此端到端收益已经很小。
4. `6` 线程时，绑核与不绑核已经非常接近，端到端只剩轻微收益。
5. 因此，第4章里“绑核优于不绑核”的写法不能写成绝对结论，更准确的表述应为：
   - 绑核在较低线程数下收益更明显；
   - 当线程数已经较高时，收益会减弱，甚至只体现在单阶段而非整体。

## 对后续子任务的影响

- 子任务2（Prefill 线程数扫描）需要继续做，因为从当前结果看，Prefill 最优线程数很可能继续偏向更高线程数。
- 子任务3（Decode 线程数扫描）也必须独立做，因为 `5` 线程 Decode 仍然优于 `6` 线程，已经出现与 Prefill 不同的最优点迹象。
