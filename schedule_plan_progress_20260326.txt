基于真机 Capacity 的混合调度改造与验证计划 - 当前实现状态
生成时间: 2026-03-26

一、已实现
1. llm_bench 已增加调度相关 CLI，并贯通到 runtime 配置: --sched-policy, --prefill-static-ratio, --decode-static-ratio, --prefill-dynamic-blocks, --decode-dynamic-blocks, --sched-sweep。
2. llm_bench_aecs 已支持显式调度参数优先级。CLI 显式传入的 policy/static_ratio/dynamic_target_chunks 优先；未显式传入时，dynamic 默认 static_ratio=0，guided 默认 prefill=0.05、decode=0.02。
3. CPURuntime 已读取真机 cpu_capacity/capacity，失败时回退 cpuinfo_max_freq，并把 capacity 写入 CPUGroup。
4. CPUBackend 新的任务划分已按活跃 CPU 的真实 capacity 权重生成 thread weights，不再依赖 cpuDecreaseRate 近似。
5. AutoTuner 已新增 SchedulerPolicy、phase-specific TuningParams、core_capacities，以及 schedule stats 统计接口。mCoreRatios 兼容接口已映射到 mCoreCapacities。
6. 现有 hybrid 路径已改为按 total_size/target_chunks 定 step。prefill 默认 target_chunks=4*T，decode 默认 target_chunks=2*T。
7. guided 调度已实现：先按 capacity 做静态 seed，再用 guided dynamic 抢占；chunk 公式为 max(min_chunk, ceil(remaining / (2*T)))。
8. guided 的退化条件已实现：任务量过小时退化为纯 dynamic；高方差且小任务时也禁用静态 seed。
9. ConvInt8TiledExecutor 仍保持区间式执行，静态和动态都通过 [start, end) 连续区间传给执行路径，没有回退到逐任务循环。
10. llm_bench 已增加调度日志: [llm_bench] Scheduler config ... 以及 [llm_bench][sched][PREFILL/DECODE] ...，并输出 tok/s、latency 和调度统计。
11. 调度统计已覆盖计划里的核心字段: total_size, total_static, dynamic_size, step_size, theoretical_dynamic_chunks, actual_dynamic_chunks(fetch_add/claim 次数), per-thread static/dynamic task loads。

二、部分实现
1. CLI 仍保留 --prefill-dynamic-blocks/--decode-dynamic-blocks 这个名字，但内部实际语义已经改成 dynamic_target_chunks。接口名未重命名，行为已按 target_chunks 生效。
2. AECS/bench 已能带着 schedule_config 和 core_capacities 运行，但 run_perfetto_batch.sh 还没有看到成体系的 sweep/判定/汇总逻辑。
3. ConvInt8TiledExecutor 已保存 mDynamicPolicy/mDynamicTargetChunks/mDynamicMinChunkSize，但当前执行期 initDynamicTaskState 主要仍从 AutoTuner 当前 phase 配置取默认值；功能上可用，成员本身还没有完全消化掉。

三、尚未实现或未验证
1. 计划中的两轮测试矩阵（四组绑核、6 类 workload、warmup=2、measure=5、取 median）还没有自动化落地，也没有提交结果。
2. 目前还没有给出 static_ratio 最优值的实测结论，也没有验证 static_ratio=0 是否在全部 case 最优。
3. guided 是否满足几何平均 tok/s +2%、单 case 回归不超过 1%、fetch_add 次数下降 30%，目前还没有实验数据。
4. 默认策略选择规则尚未收口到代码：当前默认仍是 sched-policy=dynamic，不是 guided。
5. run_perfetto_batch.sh 尚未看到针对新调度摘要日志的批量抓取/统计改造。
6. Perfetto 额外指标（worker 落核分布、主线程等待时间、静态尾拖时长）尚未在脚本或报告流程中自动汇总。

+static bool parseScheduleSweepSpec(const std::string& spec,

+    std::stringstream stream(spec);

+        }
+        const std::string key = segment.substr(0, pos);
+        const std::string values = segment.substr(pos + 1);

+        } else if (key == "decode") {
+            *decode_values = splitString<float>(values, ',');

+        }
